# Requirements Document

## Introduction

This document specifies functional enhancements for the Nexus MIA Business Model Co-Pilot application. The enhancements address user feedback across the landing page experience, guided input workflow, output generation quality, navigation, persistence, and interactive feedback. The goal is to transform the app from a linear generation tool into an interactive, voice-enabled co-creation experience with clear feedback loops and user control.

## Glossary

- **Copilot**: The Nexus MIA Business Model Co-Pilot React application
- **Guided_Input**: The conversational phase where users answer questions to build their business story (phases 1–3 of the input flow)
- **Onboarding_Screen**: The landing/front page shown when users first open the application
- **Tour_Walkthrough**: A step-by-step guided demonstration showing how to use the application from start to finish
- **Voice_Input**: Speech-to-text functionality using the Web Speech API via the useVoiceInput hook
- **Story_Summary**: A mirrored-back summary of the user's input that the system presents for confirmation before proceeding
- **Dynamic_Questions**: Follow-up questions generated by the Gemini LLM based on user keyword analysis
- **Information_Tooltip**: A hover-over or click-expand UI element triggered by an (i) icon that provides contextual explanations
- **Refinement_Invitation**: A pencil icon (✏️) displayed after each output block as a proactive prompt for user edits
- **Feedback_Acknowledgment**: A visible system response showing what changes the system made after a user refinement
- **BMC_Canvas**: The Business Model Canvas step (Step 8) displaying 9 Osterwalder blocks
- **Step_Navigation**: The workflow progression through the 9 steps from Story Input to Business Plan
- **LocalStorage_Persistence**: Browser-based storage using the useLocalStorage hook to save and resume user progress

## Requirements

### Requirement 1: Epistemic Scaffolding on Onboarding Screen

**User Story:** As a new user, I want expandable information tabs on the "What I can do" section, so that I can understand the capabilities of the application before starting.

#### Acceptance Criteria

1. WHEN the user clicks or hovers on an (i) icon within the "What I can do" capability cards on the Onboarding_Screen, THE Copilot SHALL display an Information_Tooltip with a detailed explanation of that capability
2. THE Copilot SHALL render an (i) icon next to each capability item in the "What I can do" card on the Onboarding_Screen
3. WHEN the Information_Tooltip is displayed, THE Copilot SHALL allow the user to dismiss the tooltip by clicking outside it or pressing the Escape key

### Requirement 2: Guided Tour Walkthrough

**User Story:** As a first-time user, I want a "Take a tour" walkthrough, so that I can understand the full workflow before creating my own plan.

#### Acceptance Criteria

1. WHEN the user clicks the "Take a tour" button on the Onboarding_Screen, THE Copilot SHALL display a step-by-step guided Tour_Walkthrough demonstrating the business plan generation process from start to finish
2. THE Tour_Walkthrough SHALL cover all 9 workflow steps with example data showing how each step builds on the previous one
3. THE Tour_Walkthrough SHALL display a progress indicator showing the current position within the tour
4. WHILE the Tour_Walkthrough is active, THE Copilot SHALL provide "Next", "Back", and "Exit tour" navigation controls at each tour step
5. WHEN the user completes or exits the Tour_Walkthrough, THE Copilot SHALL return the user to the Onboarding_Screen with the option to start creating

### Requirement 3: Voice Input Integration

**User Story:** As a user, I want to use voice commands throughout the application, so that I can provide input hands-free and more naturally.

#### Acceptance Criteria

1. THE Copilot SHALL display a microphone icon button on every text input field and text area throughout the application
2. WHEN the user activates the microphone button, THE Voice_Input SHALL begin capturing speech and display a visual indicator showing active listening state
3. WHILE Voice_Input is active, THE Copilot SHALL display a real-time transcript of recognized speech in the associated input field
4. WHEN the user stops speaking or deactivates the microphone, THE Voice_Input SHALL finalize the transcript and populate the associated input field with the recognized text
5. IF the Voice_Input encounters a recognition error, THEN THE Copilot SHALL display an error message with a recovery suggestion and allow the user to retry or type manually
6. IF the browser does not support the Web Speech API, THEN THE Copilot SHALL hide the microphone icon and rely on text-only input

### Requirement 4: Story Summary Confirmation

**User Story:** As a user, I want the system to mirror back what it understood from my input, so that I can verify accuracy before the system builds on my story.

#### Acceptance Criteria

1. WHEN the user completes the Guided_Input phase (all story questions answered), THE Copilot SHALL display a Story_Summary showing a structured interpretation of the user's responses
2. THE Story_Summary SHALL present the system's understanding organized by key categories: business basics, problem and solution, and target customers
3. WHEN the user clicks "Confirm", THE Copilot SHALL proceed to generate the Driver and Focus step using the confirmed story
4. WHEN the user clicks "Refine/Edit", THE Copilot SHALL return the user to the relevant Guided_Input section with previous answers preserved for editing
5. THE Copilot SHALL only proceed to generate subsequent steps after receiving explicit user confirmation of the Story_Summary

### Requirement 5: LLM-Powered Dynamic Follow-Up Questions

**User Story:** As a user, I want the system to ask intelligent follow-up questions based on my answers, so that it can gather richer context for my business plan.

#### Acceptance Criteria

1. WHEN the user answers a question during the Guided_Input phase, THE Copilot SHALL analyze user keywords and context using the Gemini LLM to determine whether a Dynamic_Question is appropriate
2. WHEN Dynamic_Questions are generated, THE Copilot SHALL present them as natural conversational follow-ups within the chat interface
3. THE Dynamic_Questions SHALL build contextually on previous user responses within the same phase
4. THE Copilot SHALL limit Dynamic_Questions to a maximum of 2 follow-up questions per base question to prevent conversation fatigue
5. WHEN a Dynamic_Question is presented, THE Copilot SHALL allow the user to skip it and proceed to the next base question

### Requirement 6: Remove Visible JSON References

**User Story:** As a user, I want a clean interface free of technical implementation details, so that the experience feels polished and professional.

#### Acceptance Criteria

1. THE Copilot SHALL NOT display any text containing "JSON structure", "JSON format", or internal data format references in any user-visible interface element
2. WHEN the system presents refinement instructions or guidance text, THE Copilot SHALL use plain language descriptions instead of technical format references
3. THE Copilot SHALL not expose internal prompt engineering terminology or data structure details to the user in any step output

### Requirement 7: Back Navigation Between Steps

**User Story:** As a user, I want to navigate back to previous steps, so that I can review and refine earlier outputs without starting over.

#### Acceptance Criteria

1. THE Copilot SHALL display a "Back" button on every workflow step except the first step (Story Input)
2. WHEN the user clicks the "Back" button, THE Step_Navigation SHALL navigate to the immediately previous step
3. WHEN the user navigates back to a previous step, THE Copilot SHALL display the previously generated output for that step
4. WHEN the user navigates back and then forward again, THE Copilot SHALL preserve all previously generated outputs for subsequent steps
5. WHILE on a previous step after navigating back, THE Copilot SHALL allow the user to refine that step's output and regenerate downstream steps if requested

### Requirement 8: Progress Persistence and Resume

**User Story:** As a user, I want my progress saved automatically, so that I can close the browser and continue later without losing work.

#### Acceptance Criteria

1. THE LocalStorage_Persistence SHALL save the complete workflow state including current step, all generated outputs, user story, and completed steps with debounced writes
2. WHEN the user returns to the application with saved progress, THE Copilot SHALL display a resume dialog offering to continue from where the user left off or start fresh
3. WHEN the user chooses "Resume", THE Copilot SHALL restore the exact workflow state including the current step position and all generated outputs
4. WHEN the user chooses "Start fresh", THE Copilot SHALL clear all saved state and present the Onboarding_Screen
5. IF the LocalStorage_Persistence encounters a storage quota error, THEN THE Copilot SHALL continue operation without persistence and log a warning to the console

### Requirement 9: Information Tooltips Throughout the App

**User Story:** As a user, I want contextual help available on demand, so that I can understand unfamiliar terms and concepts without leaving the workflow.

#### Acceptance Criteria

1. THE Copilot SHALL display an (i) icon next to key terms, step titles, and complex concepts throughout the workflow
2. WHEN the user hovers over or clicks an (i) icon, THE Copilot SHALL display an Information_Tooltip with a plain-language explanation
3. THE Information_Tooltip SHALL be dismissible by clicking outside it, moving the mouse away (on hover), or pressing Escape
4. THE Information_Tooltip SHALL be accessible via keyboard focus and announce its content to screen readers

### Requirement 10: Visible Feedback Acknowledgment

**User Story:** As a user, I want the system to acknowledge my refinements and show what it changed, so that I trust the system is responding to my input.

#### Acceptance Criteria

1. WHEN the user submits a refinement for any step, THE Copilot SHALL display a Feedback_Acknowledgment message summarizing what changes were applied
2. THE Feedback_Acknowledgment SHALL appear above the regenerated output and persist until the user navigates away or dismisses it
3. THE Feedback_Acknowledgment SHALL describe the nature of the changes in plain language (e.g., "Updated focus areas to emphasize sustainability based on your feedback")
4. IF the system cannot meaningfully apply the refinement, THEN THE Copilot SHALL display a message explaining why and suggest alternative refinement approaches

### Requirement 11: Proactive Refinement Invitation

**User Story:** As a user, I want a visible prompt to refine after each generated output, so that I know editing is encouraged and easy.

#### Acceptance Criteria

1. WHEN an output block is generated for any step, THE Copilot SHALL display a Refinement_Invitation (pencil icon ✏️) adjacent to the output
2. WHEN the user clicks the Refinement_Invitation, THE Copilot SHALL open the refinement input area pre-focused for the user to type feedback
3. THE Refinement_Invitation SHALL be visually distinct and positioned consistently after each output block across all workflow steps
4. THE Refinement_Invitation SHALL include a short label such as "Refine this" to communicate its purpose to all users including those using screen readers

### Requirement 12: Functional Business Model Canvas

**User Story:** As a user, I want the Business Model Canvas to be fully populated from my story data, so that I receive a complete and useful output at Step 8.

#### Acceptance Criteria

1. WHEN the BMC_Canvas step is reached, THE Copilot SHALL populate all 9 Osterwalder blocks (Key Partners, Key Activities, Key Resources, Value Propositions, Customer Relationships, Channels, Customer Segments, Revenue Streams, Cost Structure) with content derived from the user's story and preceding step outputs
2. THE BMC_Canvas SHALL NOT display empty blocks when story data and preceding outputs are available
3. WHEN the user selects a SWOT value proposition in the preceding step, THE Copilot SHALL use that selected proposition as the basis for generating BMC_Canvas content
4. THE BMC_Canvas SHALL allow inline editing of individual items within each block
5. IF the Gemini LLM fails to generate BMC_Canvas content, THEN THE Copilot SHALL display an error message with a retry option

### Requirement 13: LLM-Powered Contextual Story Building

**User Story:** As a user, I want the system to generate intelligent follow-up questions based on keywords from my answers, so that it captures the full depth of my business idea.

#### Acceptance Criteria

1. WHEN the user provides an answer during the Guided_Input phase, THE Copilot SHALL extract key themes and keywords from the response using the Gemini LLM
2. THE Dynamic_Questions generated from keyword analysis SHALL be contextually relevant to the user's specific business domain and stage
3. WHEN keywords suggest an underexplored area (e.g., user mentions "sustainability" but has not described environmental impact), THE Copilot SHALL generate a targeted follow-up question addressing that gap
4. THE Copilot SHALL maintain conversational coherence by referencing the user's own words when generating Dynamic_Questions
5. WHEN all base questions and relevant Dynamic_Questions for a phase are complete, THE Copilot SHALL present a phase completion message and allow the user to continue
